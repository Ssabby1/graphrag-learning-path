# 技术演示提纲

## 1. 系统简介

一句话定义：

“这是一个基于知识图谱与 GraphRAG 的可解释学习路径推荐系统，能够围绕目标知识点，结合先修关系和自然语言解释，为学习者生成合理的学习建议。”

## 2. 推荐演示顺序

### 第一步：问题定义

- 传统章节顺序不适合个性化学习
- 学习路径需要考虑先修依赖
- 单纯大模型回答缺乏结构化证据和可解释性

### 第二步：方法与边界

- 先构建课程知识图谱
- 再基于先修关系做路径推理
- 最后结合 GraphRAG 生成带证据的自然语言解释

### 第三步：系统架构

- 前端负责交互和图谱可视化
- 后端负责路径规划、检索和解释生成
- Neo4j 负责存储课程图谱和关系

### 第四步：运行查询

推荐操作顺序：

1. 打开前端页面
2. 选择一个目标知识点
3. 指定已掌握知识点
4. 展示推荐路径
5. 再输入自然语言问题
6. 展示 GraphRAG 返回的 `answer`、`path`、`evidence`、`citations`、`meta`

## 3. 需要观察的三个结果

- 这个系统不是静态知识图谱展示，而是能做路径推理
- 这个系统不是普通问答，而是有图谱证据支撑的 GraphRAG
- 这个系统不是只做算法原型，而是完成了全栈工程实现

## 4. 常见技术问题

### 为什么选 Neo4j

因为先修关系天然适合用图结构表示，Neo4j 对节点关系查询和路径相关操作更直观。

### 为什么叫 GraphRAG

因为系统并不是只靠提示词生成答案，而是先从图谱中检索证据、规划路径，再生成回答，符合 GraphRAG 的核心思想。

### 与普通 RAG 有什么区别

普通 RAG 主要检索相关文本；本系统由先修图确定学习顺序，向量检索只负责目标识别和证据选择，不能绕过图约束修改路径。

### 当前限制是什么

- 目前实验量化还可以继续加强
- 当前图谱范围集中在单门课程
- LLM 解释部分仍有进一步提升空间

## 5. 结果总结

演示应确认以下结果：

“系统完成了从目标识别、先修路径规划、关系证据检索到受约束回答生成的完整链路，并能确定性校验路径覆盖率和引用完整性。”
