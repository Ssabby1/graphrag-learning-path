# 实验验证与结果

## 1. 验证目标

本项目的验证重点不在于追求大规模 benchmark，而在于证明以下三件事情：

- 系统能够基于先修关系生成合理学习路径
- 系统能够完成从查询到解释的 GraphRAG 全流程
- 系统能够作为完整工程系统稳定运行

## 2. 验证内容

### 2.1 后端自动化测试

后端测试覆盖了以下核心模块：

- 健康检查接口
- 图谱接口
- 路径推荐服务
- 路径解释服务
- Planner 服务
- GraphRAG 接口
- Retrieval 模块

### 2.2 前端工程验证

前端重点验证：

- 项目依赖可正常安装
- 生产构建可正常完成
- 页面可正常启动并访问

### 2.3 系统联调验证

联调重点验证：

- Neo4j 可连接
- 后端接口可访问
- 前端可发起查询并展示结果
- GraphRAG 查询结果包含结构化字段

## 3. 当前验证结果

当前仓库已经完成如下验证：

- 后端自动化测试通过：`78 passed`
- 前端构建通过：`npm run build` 成功
- 完整本地图谱祖先闭包覆盖：`1514/1514`
- 42 节点、107 条路径关系的长路径证据覆盖率：`100%`
- 生产依赖审计：`0 vulnerabilities`

## 4. 已证明的项目能力

通过上述验证，可以说明本项目已经具备以下交付能力：

- 具备可运行的完整系统
- 具备可复现的前后端交互流程
- 具备可追溯的推荐与解释输出
- 具备一定工程规范与测试支撑

## 5. 还可以继续增强的方向

后续可以继续补充：

- 基线方法对比实验
- 响应时间、路径长度、路径合法率等量化指标
- 扩展盲测案例
- 不同检索策略或解释策略的消融分析

## 6. 结果边界

当前评测用于验证工程正确性和模块方向，不声称统计泛化能力。真实外部 LLM 的 Unsupported Claim Rate 与 Faithfulness 尚未测量；版本化报告明确区分确定性 fallback、fake contract 测试和真实模型质量。
