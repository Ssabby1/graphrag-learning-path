# 答辩展示提纲

## 1. 开场介绍

可以用一句话概括项目：

“这是一个基于知识图谱与 GraphRAG 的可解释学习路径推荐系统，能够围绕目标知识点，结合先修关系和自然语言解释，为学习者生成合理的学习建议。”

## 2. 推荐展示顺序

### 第一步：讲问题

- 传统章节顺序不适合个性化学习
- 学习路径需要考虑先修依赖
- 单纯大模型回答缺乏结构化证据和可解释性

### 第二步：讲方法

- 先构建课程知识图谱
- 再基于先修关系做路径推理
- 最后结合 GraphRAG 生成带证据的自然语言解释

### 第三步：讲系统

- 前端负责交互和图谱可视化
- 后端负责路径规划、检索和解释生成
- Neo4j 负责存储课程图谱和关系

### 第四步：做演示

建议按这个操作顺序：

1. 打开前端页面
2. 选择一个目标知识点
3. 指定已掌握知识点
4. 展示推荐路径
5. 再输入自然语言问题
6. 展示 GraphRAG 返回的 `answer`、`path`、`evidence`、`citations`、`meta`

## 3. 答辩时重点强调的三点

- 这个系统不是静态知识图谱展示，而是能做路径推理
- 这个系统不是普通问答，而是有图谱证据支撑的 GraphRAG
- 这个系统不是只做算法原型，而是完成了全栈工程实现

## 4. 可能被问到的问题

### 为什么选 Neo4j

因为先修关系天然适合用图结构表示，Neo4j 对节点关系查询和路径相关操作更直观。

### 为什么叫 GraphRAG

因为系统并不是只靠提示词生成答案，而是先从图谱中检索证据、规划路径，再生成回答，符合 GraphRAG 的核心思想。

### 创新点在哪里

创新点不在单个算法突破，而在于把知识图谱、路径推理和可解释生成结合为一个可运行的学习支持系统。

### 系统的不足是什么

- 目前实验量化还可以继续加强
- 当前图谱范围集中在单门课程
- LLM 解释部分仍有进一步提升空间

## 5. 收尾总结

最后建议用这类表述收尾：

“本项目完成了从知识图谱建模、路径规划、GraphRAG 查询到前端展示的完整闭环，证明了知识图谱与可解释生成结合在学习路径推荐中的可行性和应用价值。”
