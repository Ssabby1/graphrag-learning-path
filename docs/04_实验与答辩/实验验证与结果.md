# 实验验证与结果

## 1. 验证目标

本项目的验证重点不在于追求大规模 benchmark，而在于证明以下三件事情：

- 系统能够基于先修关系生成合理学习路径
- 系统能够完成从查询到解释的 GraphRAG 全流程
- 系统能够作为完整工程系统稳定运行和展示

## 2. 验证内容

### 2.1 后端自动化测试

后端测试覆盖了以下核心模块：

- 健康检查接口
- 图谱接口
- 路径推荐服务
- 路径解释服务
- Planner 服务
- GraphRAG 接口
- Retrieval 模块

### 2.2 前端工程验证

前端重点验证：

- 项目依赖可正常安装
- 生产构建可正常完成
- 页面可正常启动并访问

### 2.3 系统联调验证

联调重点验证：

- Neo4j 可连接
- 后端接口可访问
- 前端可发起查询并展示结果
- GraphRAG 查询结果包含结构化字段

## 3. 当前验证结果

截至 2026 年 4 月 16 日，当前仓库整理完成后已完成如下验证：

- 后端自动化测试通过：`26 passed`
- 前端构建通过：`npm run build` 成功
- 当前项目目录已完成面向毕设交付的文档重组与说明补充

## 4. 已证明的项目能力

通过上述验证，可以说明本项目已经具备以下交付能力：

- 具备可运行的完整系统
- 具备可演示的前后端交互流程
- 具备可追溯的推荐与解释输出
- 具备一定工程规范与测试支撑

## 5. 还可以继续增强的方向

如果后续想进一步提升论文质量，而不是仅仅完成项目交付，推荐优先补以下内容：

- 基线方法对比实验

- 不同检索策略或解释策略的消融分析

## 6. 对毕设适用性的判断

从“本科毕业设计成品”标准看，这个项目已经够用。

如果需要进一步增强“研究性”，建议后续在论文里补充：

- 为什么使用 GraphRAG 而不是普通问答

也就是说，项目完成度已经到位，接下来更值得投入的是论文表达和实验叙事。
