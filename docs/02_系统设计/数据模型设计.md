# 数据模型设计

## 1. 图谱对象

本项目的知识图谱围绕课程学习路径构建，主要包含课程、章节和知识点三类实体，以及它们之间的层级关系与先修关系。

## 2. 节点类型

### 2.1 Course

表示课程实体，用于描述整门课程的总体信息。

建议字段：

- `course_id`
- `name`
- `description`

### 2.2 Chapter

表示章节实体，用于组织课程内容结构。

建议字段：

- `chapter_id`
- `name`
- `order`

### 2.3 Concept

表示知识点实体，是推荐和推理的核心对象。

当前项目中概念节点的常用字段包括：

- `concept_id`
- `name`
- `description`

## 3. 关系类型

- `(Course)-[:HAS_CHAPTER]->(Chapter)`
- `(Chapter)-[:HAS_CONCEPT]->(Concept)`
- `(Concept)-[:PREREQUISITE_OF]->(Concept)`

其中，`PREREQUISITE_OF` 是本项目最关键的关系类型，用于表达先修约束。

## 4. 面向服务层的数据能力

为了支撑不同服务模块，图数据库需要支持以下数据访问能力：

- 图谱概览统计：课程数、章节数、概念数、先修关系数
- 知识点详情查询：获取某个概念的名称、描述、所属章节、前驱和后继
- 概念语料获取：为 planner 和 retrieval 模块提供概念文本集合
- 先修子图抽取：为路径规划服务提供目标概念的依赖子图

## 5. 当前项目中的数据输入

项目当前运行使用：

- `data/seed/concepts.csv`
- `data/seed/relations.csv`

原始章节级整理材料和数据整合过程保存在：

- `章节数据/`

该部分更适合作为数据支撑附件或论文附录材料。

## 6. 数据模型设计价值

本项目的数据模型不是简单存储知识点清单，而是围绕“路径推荐”这一目标做设计，重点体现在：

- 用图结构表达先修依赖
- 用层级关系保留课程组织信息
- 用概念语料支撑自然语言识别与 GraphRAG 检索
- 为后续增加多课程、多学科图谱留出扩展空间
