# 系统架构设计

## 1. 总体架构

系统采用典型的前后端分离 B/S 架构，由以下四部分组成：

- Vue 3 前端：负责概念搜索、路径展示、图谱可视化与 GraphRAG 交互
- FastAPI 后端：负责接口编排、路径规划、检索融合和解释生成
- Neo4j 图数据库：负责存储课程图谱、概念节点和先修关系
- 数据与脚本层：负责知识图谱导入、校验和实验支撑

## 2. 核心模块划分

### 2.1 前端模块

- 图谱视图：展示概念节点和关系
- 查询交互：输入目标知识点或自然语言问题
- 路径结果展示：展示推荐路径、证据和解释
- 双语与可视化呈现：增强演示效果和可读性

### 2.2 后端模块

- `graph` 接口模块：提供图谱概览、概念详情、概念语料查询
- `path` 接口模块：提供路径推荐与路径解释
- `planner` 接口模块：把自然语言学习请求解析成结构化目标
- `graphrag` 接口模块：整合路径规划、混合检索、解释生成
- `repositories`：封装对 Neo4j 的访问
- `services`：封装路径规划、解释生成、GraphRAG 编排逻辑
- `retrieval`：封装 graph hit、vector hit、RRF 融合和 rerank 相关逻辑

## 3. 核心处理流程

系统的主流程可以概括为：

`用户问题 -> 目标识别 -> 图谱路径推理 -> 混合检索 -> 解释生成 -> 结构化输出`

### 3.1 路径推荐流程

1. 用户选择目标知识点，并可提供已掌握知识点集合。
2. 后端从 Neo4j 中抽取目标知识点的先修子图。
3. 路径服务根据先修依赖进行拓扑排序。
4. 过滤掉已掌握知识点后，返回推荐学习路径。
5. 解释服务生成 reasoning steps 和自然语言说明。

### 3.2 GraphRAG 查询流程

1. 用户输入自然语言问题和目标概念。
2. 后端先调用路径推荐服务得到路径与证据。
3. 再根据路径和问题执行混合检索。
4. 通过 grounded answer 模板整合证据和路径。
5. 返回 `answer`、`path`、`evidence`、`citations`、`meta` 等结构化字段。

## 4. 模块间关系

- 前端只与 FastAPI 接口交互，不直接访问图数据库
- FastAPI 通过 `GraphRepository` 统一访问 Neo4j
- `planner_service` 和 `graphrag_service` 属于更高层编排逻辑
- `path_service` 负责确定性推理
- `retrieval` 模块负责为回答提供补充证据

## 5. 架构特点

- 结构清晰：检索、推理、生成三个阶段职责分明
- 可解释：路径、证据、引用和元信息均可直接展示
- 可扩展：后续可以接入更多课程图谱、更多向量后端或更强的 LLM
- 可演示：系统具备完整前端界面和接口文档，适合答辩现场展示
